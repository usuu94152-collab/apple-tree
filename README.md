# ✳ 슝슝 그림 놀이터

작은 손끝의 그림을 커다란 동화 속 세상으로 보내는 한국어 웹 놀이터. 태블릿에서 꾸민 실제 그림을 Socket.IO 서버가 같은 놀이방의 PC/TV로 전달합니다. 가입, 광고, 점수, 유료 API 없이 동작합니다.

## 시작

Node.js 24 권장(22 이상), npm. 별도 DB나 API 키는 필요 없습니다.

```sh
npm ci --cache /tmp/swoosh-npm-cache
npm run dev
```

개발 서버: Vite 5173, Express 3000. 브라우저에서 개발 서버의 `/`를 엽니다. Vite가 Socket.IO를 Express로 프록시합니다. LAN 테스트는 PC의 실제 LAN IP와 포트 5173을 사용하고 방화벽을 허용하세요. `localhost`와 사설 IP는 서로 다른 인터넷 네트워크를 연결하는 주소가 아닙니다.

```sh
npm run build
npm start
```

운영 모드는 Express 하나가 `dist/client`와 Socket.IO를 함께 제공합니다. `PORT` 기본값 3000, 바인딩 `0.0.0.0`. `.env.example`은 참고용이며 `.env` 자동 로더를 사용하지 않습니다. 필요하면 셸 또는 호스팅 설정에 `PORT`를 지정하세요. `/api/health`에서 JSON 상태를 확인합니다.

## 함께 놀기

1. PC 또는 TV의 브라우저에서 같은 서비스 주소의 `/display`를 엽니다. 예측하기 어려운 6자리 코드와 QR 코드가 생깁니다.
2. 태블릿으로 QR을 스캔하거나 `/draw`에서 방 코드를 입력합니다. 여러 태블릿이 함께 참여할 수 있습니다.
3. 사과·물고기·풍선·별을 골라 8색 펜으로 자유롭게 꾸밉니다. 굵은 펜, 지우개, 실행 취소, 확인 후 전체 지우기를 지원합니다.
4. `슝! 날려 보내기`를 누릅니다. 또는 `다 그렸어요`를 누른 후 그림을 위로 75px 이상 밀어 놓습니다. 아래로 되돌리거나 `더 그릴래요`로 취소합니다. 평상시 위로 그리는 동작은 발사가 되지 않습니다.
5. 큰 화면에 동일한 색과 선을 가진 그림이 등장합니다. 사과는 나무에 매달리고 물고기는 연못을 헤엄치며 풍선은 떠오르고 별은 반짝입니다. 그림을 톡 누르면 반응합니다.

TV의 ⚙ 메뉴에서 전체 화면, 효과음, 코드 확인, 확인 후 초기화·종료를 사용할 수 있습니다. 소리는 브라우저 정책상 첫 사용자 입력 후 활성화됩니다. 무음 상태에서도 전송 상태를 확인할 수 있습니다.

## 구현 구조

```text
client/src/
  pages/           Home / Draw / Display
  components/      DrawingCanvas / Scenery
  objects/         직접 만든 SVG 4종과 확장용 catalog
  game/            requestAnimationFrame World / Web Audio sound
  network/         같은 출처 Socket.IO 클라이언트
  styles/          반응형 한국어 UI
server/src/
  app.ts           방·권한·이미지 검증, 속도 제한, HTTP/Socket.IO
  index.ts         서버 시작
shared/protocol.ts 공통 Artwork / Reply / 제한 상수
 tests/            서버 통합 테스트, Playwright 브라우저 테스트
railway.json       운영 빌드·실행·상태 검사
```

도화지는 512×512 논리 좌표를 사용하므로 회전·리사이즈 시 그림이 유지됩니다. 포인터 캡처와 연속 선으로 손가락, 마우스, 펜을 처리합니다. 흰 도안, 자유 드로잉, 투명 윤곽선을 분리하며 전송 시 실루엣 마스크를 적용한 뒤 윤곽선을 다시 올립니다. 편집 중 바깥 낙서는 유지하고 최종 PNG 배경은 투명합니다. 방별·오브젝트별 획은 브라우저 localStorage에 보관합니다(지우거나 전송 성공하면 해당 초안 초기화).

새 오브젝트는 `shared/protocol.ts` 종류, `objects/catalog.ts` SVG·메타데이터, `game/World.tsx` 행동을 추가하면 됩니다. 현재는 공유 프로토콜과 카탈로그가 형태·이름·도안·애니메이션을 정의하며, 수신 그림마다 메시지 ID, 생성 시각, 실제 합성 PNG가 연결됩니다.

## 통신과 복구

- 예측 불가능한 6자리 방 코드, 디스플레이 재접속용 256비트 소유 토큰. 토큰은 해당 탭의 sessionStorage에만 보관합니다.
- 서버가 입장을 승인한 드로잉 소켓만 자신의 방에 전송할 수 있습니다. 보호자 작업은 디스플레이 소켓으로 제한합니다.
- PNG 최대 400KB, 512×512, 실제 이미지 디코딩 검증(sharp), 허용된 오브젝트 종류와 ID 확인. Socket.IO 패킷 크기도 제한합니다.
- 전송 간격 800ms와 처리 중 잠금, 방 생성·입장·복원은 IP당 분당 25회. 프록시 헤더를 신뢰하지 않으므로 호스팅 프록시 뒤에서는 여러 사용자가 제한을 공유할 수 있습니다. 큰 규모에서는 신뢰 프록시·분산 제한 설계가 필요합니다.
- 고유 messageId로 최근 500건 중복 방지. 서버의 전달 ACK와 TV에서 이미지 디코딩·등장 프레임 준비 후 보내는 표시 확인을 구분합니다. 확인 전에는 그림을 비우지 않습니다.
- 실패 시 원본과 동일 ID를 메모리에 유지하고 재전송합니다. 재접속 시 자동 재입장합니다. 표시 확인을 못 받으면 9초 후 다시 보내기를 제공합니다. 전송 대기 중 편집은 잠깁니다.
- TV 재접속·새로고침 시 소유 토큰으로 복원하고 최근 30개를 재표시합니다. TV가 끊기면 새 그림은 거절하고 2분 유예 후 방을 정리합니다. 방당 최대 30개, 초과 그림은 오래된 순서로 부드럽게 퇴장합니다.
- 서버 메모리에만 방과 최근 그림을 보관합니다. 디스크 영구 저장은 하지 않습니다. 재시작하면 방이 사라지므로 새 코드를 받으라는 안내가 표시됩니다. 초기화·종료 시 그림 메모리를 비웁니다.

## 테스트

```sh
npm test
npm run build
npm run test:e2e
```

브라우저 테스트는 시스템 `/usr/bin/chromium`을 기본 사용합니다. 다른 시스템에서는 Playwright Chromium을 설치하고 `PLAYWRIGHT_CHROMIUM_EXECUTABLE`에 실행 파일 경로를 지정하세요. 테스트 설정은 실제 운영 서버를 자동 시작하며 `/api/health`로 준비 상태를 확인합니다.

자동 검증 범위: 실 WebSocket 연결, 방 권한·잘못된 코드·유형·이미지·용량 거절, 중복 방지, 속도 제한, 표시 확인, TV 연결 끊김과 복원, 초기화·종료, 30개 제한. 브라우저에서는 네 종류의 실제 색칠 PNG 전달, 도구 선택, 터치 입력(CDP), 되돌리기, 투명 PNG 픽셀, 화면 새로고침과 리사이즈, 오프라인 그림 보존·재전송을 확인합니다. 스크린샷은 `test-results/`에 생성됩니다.

실제 기기 수동 확인:

- iPad Safari, Android Chrome, S Pen에서 빠른 획·점·지우개·취소·전체 지우기, 세로/가로 회전 중 획 보존을 확인합니다.
- 도안 바깥 낙서를 한 뒤 전송하여 바깥은 투명하고 윤곽선과 두 색이 보존되는지 확인합니다.
- 완성 모드 위로 발사와 아래로 취소, 그리는 중에는 발사되지 않는지 확인합니다.
- TV 브라우저의 전체 화면, 첫 터치 후 소리, 무음, 클릭 반응을 확인합니다.
- 한쪽은 휴대폰 모바일 데이터, 다른 쪽은 가정 Wi-Fi로 공개 HTTPS 주소에 접속해 QR·전송·재접속을 확인합니다.
- 30분 이상 연속 놀이 중 CPU·메모리·프레임을 관찰하고 31번째 그림이 오래된 그림을 퇴장시키는지 확인합니다. 장시간 메모리 프로파일링과 실제 기기 60fps는 자동 테스트로 보장하지 않습니다.

## Railway 인터넷 배포

1. 이 프로젝트를 GitHub 저장소에 저장하고 Railway에서 해당 저장소를 연결합니다. 이 작업에서는 원격 push나 실제 배포를 수행하지 않았습니다.
2. Node 서비스로 생성합니다. 빌드 `npm ci && npm run build`, 실행 `npm start`입니다. `railway.json`에도 정의되어 있습니다.
3. Railway가 제공하는 `PORT`를 사용합니다. 공개 도메인을 생성하고 HTTPS 주소를 확인합니다.
4. `/api/health`, `/draw`, `/display` 직접 접근 및 새로고침을 확인합니다. 모든 브라우저는 같은 공개 주소를 사용합니다. QR에는 현재 페이지의 실제 origin과 room 코드가 들어갑니다.
5. 브라우저 개발자 도구에서 `/socket.io/`의 WebSocket 연결과 그림 전송을 확인합니다. HTTPS 페이지에서는 같은 출처 WSS로 연결하며 폴링 폴백도 지원합니다.
6. TV에서 방을 만들고 다른 인터넷 네트워크의 태블릿으로 접속해 실제 전송을 확인합니다.

서비스 요금, 무료 제공 범위, 배포 UI는 바뀔 수 있으며 무료 호스팅은 보장하지 않습니다. 이 MVP는 단일 Node 인스턴스를 사용합니다. 여러 인스턴스를 운영하려면 공유 방 저장소, Socket.IO 어댑터와 세션 라우팅이 추가로 필요합니다. 방 코드를 아는 사용자가 입장하는 가벼운 놀이방 모델이며 민감한 그림 저장 서비스로 설계하지 않았습니다.

## 확인된 제한

외부 네트워크 실기기와 실제 인터넷 배포는 수행하지 않았습니다. 자동 테스트는 Chromium에서 실행하며 WebKit·실제 TV·S Pen은 위 수동 절차를 따릅니다. 서버 재시작 후 복원은 제공하지 않으며, 탭을 닫으면 TV 소유 토큰이 사라집니다. 전송 실패 중 탭 새로고침은 획을 보존하지만 대기 메시지 ID는 메모리 상태이므로 해당 상황에서는 중복 그림이 생길 수 있습니다. 브라우저 저장소 차단·용량 초과 시 새로고침 복원은 보장되지 않으며 현재 세션 그림은 유지됩니다.
